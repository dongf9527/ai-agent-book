# 第 2 章 　上下文工程 🔵 全书最关键的一章 ｜ 10 个实验

> 拆分自 [项目结构与十章详解](../guide/2026-10-24-项目结构与十章详解.md) ｜ [返回章节索引](README.md)

**核心问题**：上下文决定能力上限——模型再强，看不到关键信息就会做错决策。本章从 API 的消息结构（四种角色）讲到 Token 层面的缓存机制，是全书信息密度最高的一章。

**内容脉络**：API 上下文结构 → 用代码实现 Agent 核心循环 → **KV Cache 友好的上下文设计**（前缀越稳定缓存命中越高，系统提示词与工具定义的顺序直接影响 TTFT 和成本）→ 提示工程（结构化提示、流程驱动 vs 规则堆砌、Few-shot 的适用时机、工具定义设计）→ **提示注入**（上下文安全的核心威胁）→ **动态提示词与 Agent Skills**（领域能力拆成按需加载的知识包，解决提示词膨胀）→ **Agent 状态栏**（用时间戳、工具计数、TODO 等元信息增强轨迹管理）→ **上下文压缩**（6 种策略对比；核心洞察：上下文学习是检索而非推理，压缩要保住任务必需的事实）。

**实验亮点**：`kv-cache` 用真实 Kimi K2.6 记录六种上下文设计的缓存命中差异；`prompt-injection` 完成 3 攻击通道 × 4 层防御的完整攻防；`context-compression` 对比六种压缩策略。

**研究方向**：KV Cache 感知的提示架构、渐进式披露（Skills）、压缩与缓存的互补关系——这三个方向都是 2025-2026 年工业界与学术界共同的前沿。
