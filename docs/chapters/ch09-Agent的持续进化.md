# 第 9 章 　Agent 的持续进化 🟠 应用级 ｜ 9 个实验

> 拆分自 [项目结构与十章详解](../guide/2026-10-24-项目结构与十章详解.md) ｜ [返回章节索引](README.md)

**核心问题**：部署不是终点——如何从运行轨迹中获得学习信号，让 Agent 越用越强。本章回答"经验沉淀到哪"：**知识 / 指令 / 程序 / 参数**四种更新载体。

**内容脉络**：从运行轨迹获得学习信号（环境结果 / 过程规则 / LLM Rubric）→ 四种方法：将经验沉淀为知识（RAG 更新）、将经验写成指令（提示词自优化）、将经验写成程序（工具与代码的自演化）、将经验写入参数（连接后训练）→ 从更新产物到更新"更新方法" → **可长期运行的持续进化闭环**（可验证闭环的边界：当"完成"不等于"进步"；安全边界；**睡眠学习**：整合、遗忘与能力保鲜）。

**实验亮点**：`trajectory-verifier`（官方 Starter）、`prompt-auto-optimization`、`self-evolving-tools`、`self-modifying-agent`、`harness-safety-gate`。

**工程启示**：更新载体的选择取决于能力如何被表达与验证——能被规则验证的写成程序，只能被 LLM 判断的沉淀为知识/指令，量变到质变才动参数。灰度与回滚机制是进化闭环的安全网。
