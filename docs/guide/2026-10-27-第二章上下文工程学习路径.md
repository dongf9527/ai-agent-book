## 一、为什么这一章最关键：三句话定位

第一，**它回答的是 Agent 的能力上限从哪来**。第一章把上下文比作 Agent 的「眼睛」，本章开篇
就给出全书最重要的判断之一：模型智力只是基础，**上下文的质量才是 Agent 能力的真正关键**——
一个中等模型配精心组织的上下文，往往胜过顶级模型在信息匮乏下的盲目摸索。翁家翌那句
「人和模型一样，最重要的是 Context」是整章的题眼。

第二，**它是全书工程密度最高的一章**。从 API 的消息结构（四种角色 + tools 字段）到 token
层面的 KV Cache，再到 Skills 的渐进式披露与六种压缩策略，全链条贯通——后续所有章节的
技术（第四章的工具设计、第五章的 Coding Agent、第十章的多 Agent 协作）都建立在这套
上下文骨架上。

第三，**它的实验链最完整**。10 个实验覆盖「部署 → 注意力可视化 → 错误模式 → 提示消融 →
注入攻防 → Skill 实战 → 状态栏 → 压缩对比」，档位从 ★ 到 ★★★，正好构成一条由浅入深的
动手路线。

状态；压缩则在保留决策、约束、失败和来源的前提下提高历史信息密度。**

## 三、三轮学习路径（每轮带验收标准）

### 第一轮：骨架与铁律（半天，必做）

读 §「上下文：决定能力上限的关键」→ §「Agent 如何调用大模型」→ §「KV Cache 友好的上下文
设计」的**三条核心结论及其技术门槛提示框**（原理细节暂时跳过）。这一轮的目标是建立
「静态前缀 + 动态轨迹」的心智模型，其余一切技术都是这个模型上的操作。

动手配 **实验 2-1**（本地 LLM 服务部署与工具调用）：0.6B 小模型在合理提示词下就能可靠
完成工具调用——重点观察 ReAct 循环、`<think>` 标签的输出顺序结构、并行工具调用，以及
那个顺带留意的小实验（改系统提示词开头几个字符 → 首 token 延迟明显变长，这就是下一节
KV Cache 的体感）。

**验收标准**：能徒手画出图 2-4（上下文构成图），说出 system/user/assistant/tool 四种
角色各自的写入者；能默写三条铁律并各举一个反例（动态时间戳 / 滑动窗口 / 字符串拼接）。

### 第二轮：内容设计层（1–2 天，核心轮）

按 §提示工程 → §提示注入 → §Agent Skills → §Agent 状态栏 的顺序读。这一轮是「往上下文
里放什么」的完整方法论，也是与日常开发贴得最近的部分。四个板块共享同一条底层论断——
**上下文学习是检索而非推理**（详见第三轮压缩部分），所以：结构化提示降低「检索」成本，
Few-shot 提供可检索的模式，来源标记帮模型区分「指令」与「数据」，Skills 按需加载避免
无关信息稀释注意力，状态栏把该检索的结论提前算好放在注意力最高的末尾。

动手配 **实验 2-4 / 2-5 / 2-6** 三个：提示消融（信息组织打乱 → 成功率降 30%+，工具描述
移除 → 错误率 +45%，语气风格反而影响有限——这条排序值得记住）、注入攻防（3 攻击通道 ×
4 层防御对照）、论文→PPT（完整体验一次 Skill 渐进式加载的 5 步流程）。

**验收标准**：能解释「聪明新员工检验标准」为什么成立；能说出 Few-shot 该用的两种情形
与两个工程决策点（放哪、缓存稳定）；能复述状态栏两种实现（每轮替换 vs 持久追加）的
缓存代价权衡。

### 第三轮：深水区选读（按需，进阶）

三块内容**初读可以跳过**，不影响后续章节，但做生产系统前值得回来读完：

1. **注意力机制与 Chat Template 细节**（实验 2-2、Qwen3 思维链保留、DeepSeek R1→V4
   的 180° 反转、Claude preserved thinking 签名）——理解「为什么标准 API 格式不可绕过」
   的机制根源，以及跨厂商接续轨迹时的真实协议坑（第五章实验 5-1 会实测）。
2. **缓存作为架构约束**（Claude Code 四个设计决策）——缓存经济性如何反过来决定提示词
   结构、子 Agent 对齐、替换字符串冻结；「只追加、不改写」从性能建议升级为正确性要求。
3. **压缩与六种策略**（实验 2-10 ★★★）——检索而非推理的完整论证、上下文腐化概念、
   生产级五层压缩、隔离优于压缩。这一块同时是全书实验档位最高的一站。

**验收标准**：能向别人讲清 KV Cache 与 Prompt Cache 的层级区别；能说出压缩为什么「看似
矛盾、实则互补」（两次调用之间压、静态前缀永不动）；能解释子 Agent 隔离为什么优于压缩。

## 五、与本书仓库已有实践的连接（本仓库特色环节）

这一节把第二章与我们已完成的实验 1-1 工作台接起来——第二章的每个大主题，在我们的
五臂消融数据里都有一个现成的落点：

- **KV Cache 命中率对照**：实验 1-1 两次 canonical 的缓存命中率——Ollama 本地 80.6%
  vs Kimi 云端 48.0%——正是「Prompt Cache 跨请求复用」的现实数据点。两次跑的五臂顺序
  与消息构造完全一致，命中率差异来自服务端缓存策略与前缀构成的叠加，这是「记录不归因」
  的又一个案例，也是 2-3 实验（缓存友好设计）的天然引子。
- **no_reasoning 臂 = 思维链协议谱系的一次实测**：第二章讲 DeepSeek R1 剥离历史思考 →
  V4 强制回传 reasoning_content → Claude preserved thinking 签名绑定前缀。我们实验 1-1
  的 no_reasoning 臂就是在 wire 上剥除 reasoning（Kimi 跑实测剥除 9,149 个 reasoning
  token 仍 correct）——手册里「推理携带 why、工具结果携带 what」的消融验证，与本章
  协议谱系互为印证。
- **温度守卫 = 「厂商 API 约束」的活样本**：`_reasoning_safe_temperature` 把 kimi-kN.M
  钉死 temp=1，对应本章反复出现的主题——服务商的约束（缓存计费、固定温度、强制回传）
  是架构的前置条件而非事后优化。
- **消融方法论同源**：第二章实验 2-4 用「逐个移除系统组件」的消融法验证提示工程各要素
  贡献；我们实验 1-1 的五臂用的正是同一方法。读完第二章的「信息组织打乱 → 降 30%」，
  回头看五臂里 no_history/no_tool_results 双臂撞上限的行为，会有新的理解角度——
  组织方式与信息通道是两个正交的轴。

## 六、核心论断自测清单（读完应能脱稿说清）

1. 上下文的质量，而非模型参数量，决定 Agent 在业务中的能力上限。
2. 模型 API 无状态：每次调用必须重建完整上下文；Agent 框架的核心工作就是管理 messages 列表。
3. 三条铁律：静态前缀（系统提示词+工具定义）一旦确定不要改；动态信息永远追加到末尾；
   使用标准 API 消息格式，不要自行拼接字符串。
4. KV Cache 加速单次请求、Prompt Cache 复用跨请求前缀；缓存读取成本约为普通输入的 1/10。
5. 缓存经济性是架构的前置约束：缓存边界决定提示词结构，子 Agent 要与父 Agent 字节级对齐。
6. 提示工程排序：信息组织 > 工具描述 > 语气风格（消融实验的 30%+ / 45% / 有限）。
7. 提示注入的本质是指令与数据不分；上下文层防御只是第一道防线，Skill 与状态栏是新的注入面。
8. Skills = 渐进式披露：少量目录常驻、正文按需加载、追加到末尾不破坏缓存。
9. 上下文学习是检索而非推理：模型擅长查找、不擅长就地归纳统计——状态栏与压缩都是在给
   「只有一半的检索引擎」补上提炼层。
10. 压缩与 KV Cache 互补：静态前缀永不动，只在两次调用之间压缩轨迹；接近阈值时批量压。
11. 隔离优于压缩：让大体积中间信息根本不进主上下文（子 Agent 上下文隔离）。

## 七、思考题攻略提示（9 题中的仓库关联标注）

9 道思考题按 ★ 标注难度。与本书仓库实践直接相关的三道值得优先做：

- **Q1（★★★，滑动窗口 vs 完整历史）**：实验 2-3 发现滑动窗口让 Agent 忘掉已有结果而
  重复调用——我们实验 1-1 的 no_history 臂逐字重复、no_tool_results 臂换法试探，正是
  「丢失何种上下文产生何种退化」的一手样本，可直接作为答题证据。
- **Q2（★★，R1/V4 思维链策略反转）**：我们的 no_reasoning 臂与「剥除历史思考」同构，
  判读文第四节的「真实消融 vs 空转」机理可迁移过来分析两种策略的利弊。
- **Q4（★★，状态栏投毒）**：与实验 1-1 的编造检测（groundedness 从「模型收到的消息」
  读证据）互为镜像——一个是元信息不可信，一个是证据不可信，缓解思路可以互相借鉴。

其余六题中，Q3/Q6/Q7 偏开放研究（压缩不可逆损失、检索而非推理的突破、Skills 元认知），
适合第三轮读完后写短评；Q5（提示词熵增的工程实践）与 Q9（多工具频繁变动的布局设计）
偏工程，适合结合本章「缓存作为架构约束」一节作答。

## 八、读完之后：向第三章的延伸

本章处理的是**一次任务之内**的状态更新与上下文腐化；第三章把同一思路扩展到**跨任务**
的用户记忆和共享知识库——「对远程工作友好的团队往往也对 AI Agent 友好」在第三章会
落到具体的记忆写入与检索机制上。三条研究方向（KV Cache 感知的提示架构、渐进式披露、
压缩与缓存的互补）在 2025-2026 的工业界与学术界都还在快速演进，本章给出的三条铁律是
当前生产系统的默认原则，前沿部分（可编辑 KV「笔记」）则预示它们未来可能被松动。
