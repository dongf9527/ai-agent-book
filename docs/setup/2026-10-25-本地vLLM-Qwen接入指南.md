# 本地 vLLM / Qwen 接入指南（WSL 环境）

> 回答两个问题：① 实验代码基于 Linux 还是 Windows？② 能否调用 WSL 中已部署的 vLLM 与 Qwen 模型？
> 结论先行：实验是**跨平台 Python、但按 Linux 习惯编写**，推荐在 WSL2（本身就是 Linux）中运行；**可以零代码接入 vLLM**，只需三个环境变量。

## 一、实验的平台属性：跨平台 Python，Linux 优先

全部实验依赖为纯 Python 跨平台库（openai / requests / pypdf / numpy / matplotlib / tabulate），代码本身不含 Linux 专有调用，Windows 原生 Python 理论上也能跑。但仓库的文档、命令与验证脚本均按 Linux/macOS 习惯编写：`python3 -m venv`、`source .venv/bin/activate`、`chmod 600 .env`、POSIX 路径约定等，上游作者与社区也是在 macOS/Linux 上验证的。

因此结论是：**在 WSL2 中运行就是最正解**——WSL2 是真 Linux，所有文档命令原样可用，且 vLLM 官方本就只支持 Linux（Windows 必须经 WSL2）。既然 vLLM 已部署在 WSL，实验也放进同一个 WSL 发行版，网络即 `localhost` 直连，零额外配置。

## 二、代码证据链：为什么可以零代码接入 vLLM

vLLM 的 OpenAI 兼容服务器与 Ollama 暴露的是同一套 OpenAI Chat Completions 协议，而实验的 provider 抽象恰好留了环境变量覆盖口：

```
chapter1/context/agent.py:424   OpenAI(api_key=…, base_url=…)
  └─ config.py: resolve_backend(provider)          # 共享包回退：仓库根 agentbook/
      └─ agentbook/providers/resolution.py:198     base_url=spec.resolved_base_url()
          └─ agentbook/providers/models.py:64-72   resolved_base_url()
              → 若 base_url_var 环境变量非空则覆盖默认值
```

ollama provider 的定义（`agentbook/providers/registry.py:112-122`）对我们友好的三点：默认 `base_url=http://localhost:11434/v1`（本来就带 `/v1` 后缀，与 vLLM 一致）；`requires_key=False`（key 随便填非空即可）；`base_url_var="OLLAMA_BASE_URL"`（可整体替换端点）。且该抽象是**全仓共享包**——`chapter1/context/config.py` 注释明确写着 "so every chapter stays consistent"，即十几个章节实验全部适用同一接入方式。

## 三、接入步骤（chapter1/context 实测路径）

```bash
# 0. WSL 内启动 vLLM（若已常驻可跳过）。关键：工具解析参数，Agent 实验必需
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --served-model-name qwen3:8b \
  --enable-auto-tool-choice --tool-call-parser hermes

# 1. 实验目录配置 .env（在 env.example 基础上改四行）
cd chapter1/context
cat >> .env << 'EOF'
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:8000/v1
OLLAMA_API_KEY=local-ignored
MODEL_NAME=qwen3:8b
EOF

# 2. 跑通验证
python run_experiment_1_1.py
```

三个细节说明：

- **`--served-model-name qwen3:8b` 是个取巧点**：provider 的 `default_model` 恰为 `qwen3:8b`，服务端用这个名字对外，`MODEL_NAME` 都可以不设；若坚持用原始模型名，则必须在 `.env` 设 `MODEL_NAME=Qwen/Qwen2.5-7B-Instruct`，两边对齐即可。
- **`--enable-auto-tool-choice --tool-call-parser hermes` 不可省**：消融实验的核心是工具调用（工具定义/工具结果的移除对照），Qwen 系列在 vLLM 中需显式开启工具解析，否则工具调用会以纯文本返回，实验结果失真（Qwen3 系列同样用 hermes 解析器，若版本不匹配见 vLLM 文档的 supported models 表）。
- **URL 必须带 `/v1`**：vLLM 的 OpenAI 兼容层挂在 `http://localhost:8000/v1`，漏掉后缀会 404。

## 四、网络拓扑与资源提示

- **实验与 vLLM 同在 WSL2**：`localhost:8000` 直连，本指南默认场景。
- **实验跑在 Windows 原生 Python**（不推荐但可行）：Windows 访问 WSL2 服务默认有 localhost 转发（`localhostForwarding=true`），同样用 `http://localhost:8000/v1`；若关闭过该特性则改用 WSL 的 eth0 IP（`wsl hostname -I`）。
- **显存**：7B bf16 约需 16–18 GB；显存紧张可用 AWQ/GPTQ 量化版或加 `--max-model-len 4096 --gpu-memory-utilization 0.85`。实验的 `MODEL_MAX_TOKENS=1000`、`MAX_ITERATIONS=10` 默认值对小卡友好。
- **成本收益**：此路径下阶段一全程零 API 花费，且响应延迟取决于本地 GPU 而非网络，消融对照（5 模式 × 任务套件）跑起来更快。
