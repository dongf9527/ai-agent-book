# 实验 1-1 单臂快测判读：`no_tool_results` 臂的 ERROR 是预期行为

> 环境：WSL 内 Ollama（server v0.40.11），模型 `qwen3.5:9b`，2026-10-25。
> 命令：`python run_experiment_1_1.py --provider ollama --model qwen3.5:9b --modes no_tool_results`
> 证据：`chapter1/context/validation/real_20261025T052851Z/evidence.json`（SHA-256 `70a25e7c…`）

## 一、结论先行

**没有 bug，无需修复工具包。** 那条日志——

```
ERROR - Error executing code: name 'convert_currency' is not defined
```

是 `no_tool_results` 消融臂**预期失败路径中的一环**：模型因为始终看不到工具返回值而
"病急乱投医"，试图在代码解释器的 Python 沙箱里直接调用 `convert_currency()`，而沙箱
命名空间按设计**不含任何 agent 工具**，于是抛出 `NameError`。沙箱正确地捕获、记录并把
错误作为工具结果交还（该结果同样被消融隐藏）。错误处理链路完全按设计工作。

单臂快测的核心目标——验证手稿对这臂的行为预言——**已经达成**：

```json
"without_tool_results_repeated_action": true
```

模型在三轮里重复发出完全相同的三个货币转换调用，正是《深入理解 AI Agent》实验 1-1
对"去掉工具结果"一臂的预言：**观察不到结果 → 行为不断重复**。

## 二、消融机制：`no_tool_results` 到底做了什么

工具结果并非"不发回"，而是**发回空内容**（OpenAI 协议要求 tool 消息必须存在）：

- `agent.py` L877-891：构造 tool 消息时，`NO_TOOL_RESULTS` 模式下
  `"content"` 被替换为 `self.hidden_result_content`；
- `agent.py` L40-42：两种隐藏风格——`marker`（留一条"结果被隐藏"的可见标记）与
  `empty`（静默扣留，默认值，canonical 语义）。默认 `empty` 是刻意的：对模型而言，
  "结果被扣留"与"工具没返回有用信息"本就无法区分，marker 会额外泄露"存在消融"这一信号。

于是模型的每一轮请求里，自己发出的 tool_calls 都在，但每次换回的都是空字符串。
这正是本臂要制造的观测条件。

## 三、五轮轨迹逐轮判读

| 轮次 | 模型行为 | 判读 |
|------|----------|------|
| 1 | 发出 3 个 `convert_currency`（EUR/GBP/JPY→USD） | 正常工具调用；结果被扣留 |
| 2 | **逐字重复**轮 1 的 3 个调用 | 手稿预言的 repeated_action 首次出现 |
| 3 | 再次逐字重复 | 重复模式坐实（`repeated_tool_calls > 0`） |
| 4 | 换思路：`code_interpreter` 里写 `result = convert_currency(...)` 试图自己算 | 模型开始"自救"；沙箱白名单拒绝 → `NameError`（即那条 ERROR） |
| 5 | 退化测试 `calculate('2 + 2')` | 打转；撞 5 轮上限，未产生终止回复 |

`no_terminal_response` 就是这么来的：**这臂的模型拿不到任何观测值，理论上永远算不出
答案**，在迭代上限内给出终止回复本来就难。这不是缺陷，而是该臂的正常归宿——工具包的
`arm_outcome()`（run_experiment_1_1.py L307-339）专门把"没完成"单列为
`no_terminal_response`，以区别于"完成了但编造数字"（`unsupported_numbers`）——
后者才是真正危险的失败。

值得注意的细节：模型在第 4 轮的代码里写的注释是 *"I don't have direct access to
exchange rates here"*——它**自己意识到了**观测缺失，这与 `arms_stating_unsupported_numbers: []`
（没有编造汇率）互相印证：`qwen3.5:9b` 在这臂的表现是"诚实地困住"，而非"编个答案糊弄"，
属于失败安全（fail safely）的一类。

## 四、为什么沙箱里没有 `convert_currency`

`code_interpreter` 的执行命名空间是显式白名单（agent.py L299-329）：仅含
`abs/sum/min/max/round/len/sorted/range/int/float/str/print` 等安全 builtins 加一个
`math` 模块。agent 的三个工具（`convert_currency` / `calculate` / `code_interpreter`）
**刻意不在其中**，原因有二：

1. **协议完整性**：工具只能经 tool_calls 协议由 harness 代为执行并记录轨迹。若沙箱能
   直接调工具，模型就绕开了实验要观测的"调用-观察"回路，轨迹证据（api_turns）将失真。
2. **安全边界**：模型生成的代码在受限沙箱里运行；把任意工具（含下载 PDF、联网等能力）
   注入 exec 命名空间等于把系统能力敞口给不可信代码。

所以 `NameError` 是沙箱在正确履职。那条日志级别是 ERROR 只是观感问题——它表示
"这次工具执行失败了"，而**工具执行失败本来就是 agent 运行时的常态输入**，harness 会把它
作为结果回传（并在本臂中被消融隐藏）。
