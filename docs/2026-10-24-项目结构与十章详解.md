## 一、项目定位与仓库结构

《深入理解 AI Agent：设计原理与工程实践》不是一本"教你调 API"的手册，而是一套把 Agent 从原理讲到生产可靠性工程的完整方法论。全书围绕一条公式展开，每章配可运行实验，所有结论都有真实模型运行证据支撑。理解项目结构，本质上是理解它的三层资产如何互相咬合。

### 1.1 目录结构总览


### 1.2 三层资产的分工

**正文（book/）回答"为什么"**：每章由设计原则、短伪代码与 skeleton 构成，刻意不绑定任何 SDK，保证知识不随框架换代而过时。官方 FAQ 明确说明：实验代码由 coding agent 生成，作者也不逐行审读，读者的重心应放在架构、核心组件与设计原则上。

**实验（chapter1~10/）回答"怎么做"**：109 个实验分两类——本地项目（完整实现 + 测试 + 日志）与外部复现轨道（锁定 commit 的第三方基准，如 SWE-bench、OSWorld、GAIA、tau2-bench）。每个实验 README 按"理解问题 → 准备环境 → 按步完成 → 分析结果 → 阅读实现"的学习闭环组织。

**台账（EXPERIMENT_LEDGER.md）保证"可信"**：这是本项目区别于一般教程的杀手锏。每个实验一行验收记录：冻结的验收门槛、状态（Passed/设计/未复现）、规范证据路径（manifest.json 哈希 + 原始日志）。失败结果也被保留为证据，历史百分比未被复现时会被显式标注——这是一种科学诚实，工程上值得直接搬进自己的项目。

## 二、核心框架：两个公式贯穿十章

**实现层公式：Agent = LLM + 上下文 + 工具**。LLM 是大脑（理解、推理、决策），上下文是眼睛（每个决策点能看到的全部信息：系统提示词、工具定义、历史消息、工具结果），工具是手脚（感知环境、执行操作）。学术层对应强化学习术语：策略（Policy）、观察空间（Observation Space）、动作空间（Action Space）。

**生产层公式：Agent = Model + Harness**。进入生产环境后，同一系统改写为模型加上 Harness，其中 **Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正**。后三项正是"能跑的 Demo"与"可靠产品"之间的差距——遇到问题先查 Harness，再考虑换模型，这是全书最重要的工程判断。

十章与两个公式的映射关系：第 1 章立公式；第 2–6 章逐一深化"上下文"与"工具"两大要素（构建）；第 7–9 章讲能力提升（评估 → 后训练 → 持续进化）；第 10 章把单 Agent 三要素推广到群体协作。

## 三、十章详解

### 构建篇（第 1–6 章）：建立完整的 Agent 构建方法

#### 第 1 章 　AI Agent 入门 🟢 入门级 ｜ 4 个实验

**核心问题**：Agent 到底是什么，什么决定了它的能力强弱。本章从观察空间与动作空间这对接口出发，逐一解剖三要素——LLM（大脑）提供理解与决策，上下文（眼睛）决定每次决策的信息输入，工具（手脚）决定能对世界做什么改动。

**内容脉络**：三要素解剖 → ReAct 循环（推理-行动交替的最小 Agent 形态）→ **Harness 工程：模型之外的竞争力** → 从提示工程到 Loop 工程的范式演进 → 构建有效 Agent 的核心原则 → 模型选型 → 编排模式（工作流 vs 自主）→ 护栏与安全性 → Harness 五要素与全书"构建篇"的对应。

**关键概念**：Harness 五要素（上下文供给、工具接口、约束、验证、纠正）是全书的总纲；编排模式的判断标准——任务路径可枚举用工作流，开放探索才用自主 Agent。

**实验亮点**：`context`（三要素最小实现，官方 Starter 第一课）、`image-gen-workflow`、`search-codegen`、`learning-from-experience`。

**工程启示**：读完应能用一句话回答"Demo 和产品的差距在 Harness 不在模型"，并能在自己的项目里指出这五个要素分别对应哪些代码。

#### 第 2 章 　上下文工程 🔵 全书最关键的一章 ｜ 10 个实验

**核心问题**：上下文决定能力上限——模型再强，看不到关键信息就会做错决策。本章从 API 的消息结构（四种角色）讲到 Token 层面的缓存机制，是全书信息密度最高的一章。

**内容脉络**：API 上下文结构 → 用代码实现 Agent 核心循环 → **KV Cache 友好的上下文设计**（前缀越稳定缓存命中越高，系统提示词与工具定义的顺序直接影响 TTFT 和成本）→ 提示工程（结构化提示、流程驱动 vs 规则堆砌、Few-shot 的适用时机、工具定义设计）→ **提示注入**（上下文安全的核心威胁）→ **动态提示词与 Agent Skills**（领域能力拆成按需加载的知识包，解决提示词膨胀）→ **Agent 状态栏**（用时间戳、工具计数、TODO 等元信息增强轨迹管理）→ **上下文压缩**（6 种策略对比；核心洞察：上下文学习是检索而非推理，压缩要保住任务必需的事实）。

**实验亮点**：`kv-cache` 用真实 Kimi K2.6 记录六种上下文设计的缓存命中差异；`prompt-injection` 完成 3 攻击通道 × 4 层防御的完整攻防；`context-compression` 对比六种压缩策略。

**研究方向**：KV Cache 感知的提示架构、渐进式披露（Skills）、压缩与缓存的互补关系——这三个方向都是 2025-2026 年工业界与学术界共同的前沿。

#### 第 3 章 　用户记忆和知识库 🔵 进阶级 ｜ 12 个实验

**核心问题**：如何让 Agent 在对话结束后仍然记住用户、接入外部知识——把上下文从单次会话延伸为跨会话的持久知识体系。用户记忆（个体尺度）与知识库（群体尺度）共用向量检索、知识压缩等底层技术，面临同样的信息冲突、知识过期、检索不准问题。

**内容脉络**：记忆能力评估（三层次框架 + LoCoMo 基准：平均 300 轮超长对话）→ 记忆层次结构 → 四种渐进式存储格式 → 进阶知识表示：可执行代码 → 记忆框架案例 → 记忆压缩与整理 → 隐私保护（日志脱敏）→ **RAG 基础**（分块 → 稠密嵌入 → 稀疏嵌入 → 混合检索）→ **超越扁平文本**（结构化索引、文件系统范式、知识更新策略）→ **Agentic RAG**（把检索工具化的范式转变）→ 上下文感知检索 → 知识发现 → 多模态记忆。

**实验亮点**：`user-memory` 是完整的记忆系统实现（memory_manager + 后台异步提取 + LoCoMo 评测），可直接改造接入业务；`mem0`/`memobase` 提供商业记忆框架对照；`agentic-rag`、`contextual-retrieval` 覆盖检索前沿。

**研究方向**：记忆的三层次评估框架、冲突解决与时间感知、Agentic RAG 与检索工具化、可执行代码作为记忆载体——记忆系统是当前 Agent 产品差异化的主战场。

#### 第 4 章 　工具 🔵 进阶级 ｜ 5 个实验

**核心问题**：工具是 Agent 的双手，如何分类、设计、组织，以及工具太多时怎么办。工具设计的水平直接决定 Agent 的动作空间质量。

**内容脉络**：工具五分类（感知 / 执行 / 协作 / 事件触发 / 用户沟通）→ 通用设计原则（专用工具、通用执行器与 Skill 的能力表达谱系；工具描述的艺术；参数传递的保真性）→ **工具生态：MCP 与 Skill Hub**（Model Context Protocol 标准化工具接入）→ **层次化组织与主动工具发现**（工具列表膨胀的解法：按需加载 + 模型原生的主动发现）→ 感知工具（控信息量，含多模态感知）→ 执行工具（控风险：参数校验、权限控制、LLM 二级审批、长输出处理）→ 协作工具。

**实验亮点**：`execution-tools` 是带完整安全机制的执行工具 MCP Server——输入验证、不可逆操作 LLM 审批、自动语法校验反馈闭环、超 1 万字符输出自动总结，可直接接到 Claude Code 等运行时复用；`active-tool-discovery` 演示动态工具发现。

**核心口诀**：感知工具控信息量，执行工具控风险；工具设计应通用化，接口设计决定模型行为。

#### 第 5 章 　Coding Agent 与通用 Agent 🟣 高级 ｜ 16 个实验（实验最多的一章）

**核心问题**：为什么 Coding 能力是通用 Agent 的基础，代码为什么是"能创造新工具的工具"。本章实验数量冠绝全书，因为它是官方推荐终极项目（自研 coding agent）的主参考。

**内容脉络**：Coding 是 Agent 的基础能力 → 案例研究：从 Manus 到 OpenClaw——通用 Agent 的 Coding 内核 → Coding Agent 整体流程 → Harness 工程实践（故障与错误恢复）→ 实现技巧 → 搜索工具与文件编辑工具 → 安全 → **代码作为通用 Agent 的元能力**六个方向：代码作为思考工具（用执行结果验证逻辑，而非让模型"读数据猜结论"）、代码约束业务规则、代码驱动多媒体生成、代码作为系统适配器、代码生成式 UI、代码创造代码（Agent 自举）。

**实验亮点**：`coding-agent` 是生产级 Coding Agent 骨架（文件系统 + 终端 + 编辑）；`cad-vs-diffusion`、`code-for-logic`、`code-for-math` 验证"代码即思考"；`agent-creator`、`paper-to-ppt` 展示代码元能力的应用面。

**工程启示**：面向开放任务的 Agent 无法预置所有工具，运行时自造工具（写脚本、存文件）是灵活性来源，但必须由权限控制、执行隔离与结果验证兜底。

#### 第 6 章 　交互：观察与动作空间的扩展 🟣 高级 ｜ 14 个实验

**核心问题**：把 Agent 的观察与动作空间沿"模态 × 时序"两个维度扩展——从异步消息到语音、Computer Use、机器人操作。四类交互共享同一批系统原语：唤醒、安全点、取消、抢占、快慢路径分离。

**内容脉络**：**异步与事件驱动**（当世界主动找上门：OpenClaw 的事件驱动机制、事件触发工具、用户沟通工具、虚拟身份与隔离执行环境、无原生异步时的兼容方案、GPT-6 Astra 的模型原生异步）→ **语音**（交互时序从级联流水线到端到端全模态再到全双工；认知时序：实时交互与深度思考的矛盾；更像人的语音合成）→ **Computer Use**（GUI 自动化：动作空间设计、视觉定位 Grounding、世界模型、移动端生态壁垒）→ **机器人操作**（以 XLeRobot 整理桌面为例：硬件与算法分工、长程规划、VLA 控制及其局限、世界模型、仿真到实机）。

**实验亮点**：`async-agent`、`live-audio`（官方 Starter）、`claude-computer-use-native`、`xlerobot-teleoperation` 等，覆盖从软件到具身的完整交互谱系。

**研究方向**：全双工语音的"实时响应 vs 深度思考"权衡、GUI Agent 的视觉定位、VLA（视觉-语言-动作）模型局限与世界模型补偿——这是 Agent 与物理世界打通的前沿。

### 提升篇（第 7–9 章）：评估、训练与进化

#### 第 7 章 　Agent 的评估 🟡 工程级 ｜ 14 个实验

**核心问题**：没有评估，就分不清"设计带来的提升"和"随机波动"——这是全书反复捶打的地基。本章以 τ²-bench telecom 领域为解剖样本，把一次评估任务拆到器官级。

**内容脉络**：一条评估任务的解剖（任务定义四要素 + 真实运行轨迹）→ **评估指标**（Pass@k 看能力上限，**Pass^k 看业务可靠性**——k 个环节全过才算成的业务视角）→ 评估环境五要素（人机交互型 vs 工具调用型）→ 评估数据集设计（基准横向对照、验证器、难度划分、**数据泄漏防范**、质量控制）→ **LLM-as-a-Judge**（自动化评估核心）→ **失败归因**（从整条轨迹定位首个错误）→ 端到端回归 vs 轨迹前缀回归 → 配对比较与模型排名 → 评估驱动的模型选型（行为策略、成本分析）→ 统计显著性 → 可观测性 → 从 Benchmark 报告到系统改进（数据 → 假设 → 路线图）→ 生产级评估基础设施（消融基础设施）。

**实验亮点**：`tau2-bench-eval`（官方 Starter，交互环境评价客服 Agent）、`elo-leaderboard`、`agent-cost-analysis`、`user-memory-policy-eval`。

**工程启示**：给自己的 Agent 先建一个十几条任务的小评估集再谈优化；每次只改一个变量；评估对象是整个系统（上下文、工具、验证机制变了同样要测）。

#### 第 8 章 　模型后训练 🔴 专家级（全书唯一需 ML 基础）｜ 19 个实验

**核心问题**：能力如何内化进模型参数——预训练 / Mid-training / SFT / RL 四阶段各自在做什么，何时选 SFT、何时选 RL。**SFT 记忆，RL 泛化；数据与环境比算法更重要**是本章纲目。

**内容脉络**：四阶段全景（SFT 本质是换了数据的"预测下一个词"）→ 经典 RL Agent 到现代 Agent 的动作表示演变 → Mid-training 补知识与基础能力 → SFT 与数据合成（从示范到可训练轨迹）→ 何时选择 Mid-training / SFT / RL → **单轮强化学习：记忆与泛化的对照** → RL 算法（16 次 rollout 到一次参数更新；为什么 LLM RL 优先 On-Policy）→ **RL 环境：从评估到仿真**（造不出环境就让模型扮演环境；环境、任务分布与评估隔离）→ 多轮任务与信用分配 → 工具调用把环境带进 Agent → **蒸馏**（在轨蒸馏让一次 rollout 产生密集监督；On-Policy 自蒸馏）→ 三个真实问题案例（Coding Agent 过早结束、中文引号、编辑文件失败）→ 后训练实践要点。

**实验亮点**：19 个实验覆盖 `cot-distillation`（官方 Starter）、`retool`（工具调用内化）、`MiniMind-pretrain`、`continued-pretraining`、SFT/DPO 系列。**需要 CUDA GPU 与 Python 3.12+**，依赖通过 `--extra vllm` / `--extra unsloth` 安装——这是本地 GPU 资源的用武之地。

**研究方向**：多轮信用分配、环境构造与模型扮演环境、在轨蒸馏样本效率——后训练是把评估发现的问题固化为模型能力的通路。

#### 第 9 章 　Agent 的持续进化 🟠 应用级 ｜ 9 个实验

**核心问题**：部署不是终点——如何从运行轨迹中获得学习信号，让 Agent 越用越强。本章回答"经验沉淀到哪"：**知识 / 指令 / 程序 / 参数**四种更新载体。

**内容脉络**：从运行轨迹获得学习信号（环境结果 / 过程规则 / LLM Rubric）→ 四种方法：将经验沉淀为知识（RAG 更新）、将经验写成指令（提示词自优化）、将经验写成程序（工具与代码的自演化）、将经验写入参数（连接后训练）→ 从更新产物到更新"更新方法" → **可长期运行的持续进化闭环**（可验证闭环的边界：当"完成"不等于"进步"；安全边界；**睡眠学习**：整合、遗忘与能力保鲜）。

**实验亮点**：`trajectory-verifier`（官方 Starter）、`prompt-auto-optimization`、`self-evolving-tools`、`self-modifying-agent`、`harness-safety-gate`。

**工程启示**：更新载体的选择取决于能力如何被表达与验证——能被规则验证的写成程序，只能被 LLM 判断的沉淀为知识/指令，量变到质变才动参数。灰度与回滚机制是进化闭环的安全网。

### 协作篇（第 10 章）：从个体到群体

#### 第 10 章 　多 Agent 协作 🟠 应用级 ｜ 6 个实验

**核心问题**：群体智能何时真正高于个体。本章给出**新信息判据**：只有当协作引入了单个 Agent 在生成时拿不到的新信息（审核 Agent 真正跑了测试、读了日志、看了截图），协作才产生价值；多 Agent 的每个设计决策都能在单 Agent 三要素中找到对应。

**内容脉络**：分类框架（上下文共享/独立 × 对等/管理者/去中心化拓扑）→ 共享上下文的协作 → 不共享上下文的协作（Agent 眼中的文件系统、通信与控制）→ 三种拓扑详解（对等：相互制衡与迭代改进；管理者：中心化协调；去中心化）→ **跨组织协作：A2A 协议** → **六种失败模式**（共享文件系统并发冲突、错误级联放大、同质趋同、互相扯皮、循环失控、理解债与认知投降）→ **Agent 社会**（斯坦福 AI 小镇、Agentopia 十年尺度生活模拟、Moltbook 社交网络、Vending-Bench Arena 经济竞争、Pinchwork/RentAHuman Agent 经济、狼人杀信息不对称博弈）。

**实验亮点**：`parallel-web-research`（官方 Starter，message_bus + agents 的协调骨架）、`generative-agents`、`talkact-reproduction`、`book-translation`（本书多语言版的翻译流水线本身就是一个多 Agent 项目）。

**工程启示**：搭多 Agent 前先过三问——任务真需要分工吗？不同 Agent 能拿到不同信息吗？协作收益盖得住 Token、通信与调试成本吗？六种失败模式是现成的架构评审清单。
