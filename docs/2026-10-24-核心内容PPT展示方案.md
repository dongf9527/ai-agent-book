# 核心内容 PPT 展示方案（可行性评估）

> 日期：2026-10-24 ｜ 前置文档：[项目结构与十章详解](2026-10-24-项目结构与十章详解.md)、[全书主线与学习实践计划](2026-10-24-全书主线与学习实践计划.md)
> 结论：**完全可行，且本仓库自带两条可复用的技术先例**（ch2 与 ch5 实验）。

## 1. 可行性结论

用 PPT 展示《深入理解 AI Agent》核心内容没有技术障碍，理由有三：

1. **内容已结构化**：十章详解已按"核心问题 / 内容脉络 / 关键概念 / 实验亮点 / 工程启示"逐章整理成卡片（`docs/chapters/`），每章卡片恰好可以映射为 1–2 页幻灯片，无需二次提炼。
2. **仓库自带先例**：上游项目本身就是"AI 生成 PPT"的教材——
   - `chapter5/paper-to-ppt/`：完整多 Agent 流水线（Proposer 生成 `slides.md` → Slidev 渲染逐页 PNG → Reviewer 基于截图迭代），渲染引擎为 **Slidev CLI + playwright-chromium**；
   - `chapter2/agent-skills-ppt/`：用 Agent Skills（渐进式披露）加载"如何做 PPT"的技能包，演示提议者-审核者模式。
3. **渲染链路成熟**：Markdown 驱动幻灯片（Marp / Slidev）与程序化生成（python-pptx）两条路线均有成熟工具链，中文渲染无障碍。

## 2. 三条技术路线对比

| 路线 | 技术栈 | 输入 | 输出 | 优势 | 局限 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- |
| A. Markdown 驱动 | Marp / Slidev（仓库 ch5 同款） | `slides.md` | .pptx / .pdf / 逐页 PNG | 与全书 Markdown 工作流一致，可进 git 版本管理、diff 友好；ch5 有现成参考实现 | 精细排版依赖主题 CSS；导出 .pptx 后文字不可二次编辑（Marp） | 长期沉淀为仓库资产、随书更新 |
| B. 程序化生成 | python-pptx | Python 脚本 + 内容数据结构 | 原生 .pptx | 可编程批量生成（如自动从每章卡片生成章节页）；版式精确可控 | 需要写排版代码；样式迭代成本高于 A | 定期自动再生成、数据驱动页面 |
| C. 沙箱环境 pptx 技能 | HTML 设计稿 → 转换 .pptx | 大纲 + 设计规范 | 原生 .pptx | 排版质量最高、交付最快，适合一次性精排 | 内容变动后需重新生成，难以作为仓库内可持续流程 | 立即要一份高质量"核心内容速览"成品 |

**推荐组合**：短期用 **路线 C** 快速产出第一版精排 .pptx（作为交付物放进 `docs/ppt/` 或 `download/`）；若后续需要随书迭代、纳入六阶段学习计划的产出物，再迁移到 **路线 A**（Slidev，`slides.md` 进 git，与 ch5 实验同一技术栈，顺便完成一次 ch5 的实践预演）。

## 4. 实施注意事项

- **中文渲染**：Marp/Slidev 需在 CSS 中显式指定中文字体（如 Noto Sans SC / 思源黑体），否则回退字体导致排版错位；python-pptx 则依赖本机字体库。
- **图表来源**：可复用仓库内现成 SVG/PNG（实验产物 1994 个 svg、896 个 png），第 2/3/13 页建议配架构示意图。
- **素材一致性**：幻灯片内容以 `docs/chapters/` 卡片为唯一事实源，避免两处维护（卡片更新 → 幻灯片脚本同步）。
- **提交规范**：PPT 源文件与成品均放 `docs/ppt/`，以 `docs:` 前缀小步提交；若走 Slidev 路线，构建依赖走 `package.json`（参考 ch5 的 workspace 结构）。
