## 一、验证的三个层次：复核 ≠ 复现

"验证一个实验是如何进行的"有三个层次，成本递增、证明力递增，按需选用：

| 层次 | 做什么 | 成本 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|
| **L1 完整性复核** | 机器核对证据自洽：晋升指针逐字节一致、SHA-256 sidecar 与实际文件哈希一致、验收门全真、行为账目（臂/格/fiber）齐全 | 秒级，零成本 | 仓库里的证据是完整、未被篡改、自洽的一手记录 | 证据所描述的模型行为在其他模型/时间仍然成立 |
| **L2 行为对账** | 人读证据中的关键行为（终文数值、搜索轮次、引用来源、图像内容）与 `chapter1/EXPERIMENT_LEDGER.md` 的论断逐条对照 | 分钟级 | 账本叙事没有超出证据支持范围 | 同上，另加：验收门设计本身是否充分 |
| **L3 本地复现** | 在自己的环境跑一遍实验，产出新证据并与 canonical 对照 | 小时级，需 API key 或本地算力 | 同类环境下行为可重现 | 与原跑逐字节相同（模型有非确定性，对照的是行为画像而非字节） |

L1 是日常操作（任何一次怀疑证据被改动时跑一遍即可）；L2 在账本更新或新证据入库时做；L3 是学习目的所在——这本是教学工具包，跑一遍比读十遍有效。

## 二、L1 一键机器复核（已内置 28 项断言）

## 三、四实验证据地图与 L3 本地复现命令

每个实验的证据入口统一是 `validation/latest.json`（滚动指针）+ 一次性的 `validation/real_<时间戳>/` 或 `validation/runs/<时间戳>/`（带 SHA-256 sidecar 的完整证据包）。复现命令按各自 README 的步骤节选如下：

| 实验 | 证据入口 | 所需凭据 | 本地复现 |
|---|---|---|---|
| **1-1** 上下文消融 | `chapter1/context/validation/latest.json` | 无（本地 Ollama，`ollama serve` + 已 pull 模型） | 预检探针与 canonical 命令见 [实验1-1-canonical-run命令卡](2026-10-25-实验1-1-canonical-run命令卡.md)；一行版：`python run_experiment_1_1.py --provider ollama --model qwen3.5:9b --task guarded --hidden-result empty --output-dir validation/real_<你的时间戳>`（exit 0 ⇔ accepted 并自动晋升 latest.json） |
| **1-2** Kimi 托管搜索 | `chapter1/web-search-agent/validation/latest.json` | `MOONSHOT_API_KEY` | `cd chapter1/web-search-agent && cp env.example .env`（填 key）→ `python run_experiment_1_2.py --output-dir validation/real_<你的时间戳>`；跑完看 `acceptance.checks` 是否全真 |
| **1-3** 搜索+代码执行 | `chapter1/search-codegen/validation/latest.json`（明细在 `validation/runs/real_20260731T170529Z/`） | `DASHSCOPE_API_KEY`（canonical 后端）或 `OPENAI_API_KEY`（官方路径） | `cd chapter1/search-codegen && cp env.example .env` → `python run_experiment_1_3.py --output-dir validation/real_<你的时间戳>`；验收看 `web_search_call` / `code_interpreter_call` 服务端回执而非答案自称 |
| **1-4** 文生图三路由 | `chapter1/image-gen-workflow/validation/real_20260821T040450Z/evidence.json` | `KIMI_API_KEY`（改写节点）+ `DASHSCOPE_API_KEY`（wan2.2）+ `GEMINI_API_KEY`（Nano Banana）+ `OPENAI_API_KEY`（GPT-Image） | `cd chapter1/image-gen-workflow && cp env.example .env` → `python main.py`；图像与逐调用回执落 `outputs/<run_id>/`，manifest 落 `validation/` |

复现后的对照要点（L2 行为对账的核心问题）：1-1 对比五臂 outcomes 与合同绿红；1-2 对比 fiber 数量与来源链接是否官方域；1-3 对比大圆距离与独立参考的偏差（≤ 数公里量级）；1-4 对比改写节点是否丢约束（如"深夜独处也清净"是否进了正向 prompt 而不是 negative_prompt）。

## 四、验证的边界（诚实声明）

1. **证据自洽不等于论断为真**。L1 证明"仓库记录如此"，L2 证明"论断没有超出记录"，但模型迭代很快——换模型重跑完全可能得到不同结论（1-1 的 no_reasoning 臂在 DeepSeek 基准 incorrect、本地 qwen3.5:9b correct，n=1 各自，就是活例）。账本对这类差异的表述原则是"tendencies rather than laws"。
2. **1-4 的图像本体不在仓库里**。`outputs/` 未入库（避免仓库膨胀），交付物是 evidence.json 里逐格的 SHA-256——这是约定（见 EXPERIMENT_CONVENTIONS.md），不是缺失；但要验证图像内容需本地持有对应 outputs 目录或重跑。
3. **加密回执（1-2 的 MOONSHOT ENCRYPTED fiber）本地不可解**。它是服务端托管搜索的存在性证明（本地无法伪造加密 fiber 的结构），内容级核对依赖答案中的来源链接与官方域匹配。
4. **复现 ≠ 复刻**。1-1 的 `--max-iterations 5`、temperature 等参数已固定，但 token 级输出天然非确定；对照口径是行为画像（轮数、outcome 分类、合同绿红），不是逐字节 diff。
