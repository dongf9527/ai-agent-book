## 〇、context 套件是什么（通读代码后的浓缩图）

`chapter1/context/` 四个文件构成一台"消融实验机"：

```
config.py            provider 注册解析（kimi/deepseek/dashscope/ollama/vLLM 经 OLLAMA_BASE_URL 接入）
   ↓ resolve_backend()
agent.py (1024 行)   ContextAwareAgent：ReAct 循环 + 四工具（parse_pdf/convert_currency/
                     calculate/code_interpreter）+ 五种 ContextMode 消融
   │                 ├─ NO_HISTORY:      _prepare_messages_for_api() 只留 system+最后 user（字面重启）
   │                 ├─ NO_REASONING:    _prepare_assistant_message() 双字段剥除 reasoning*
   │                 ├─ NO_TOOL_CALLS:   不声明工具 schema
   │                 └─ NO_TOOL_RESULTS: 工具消息 content 置空（静默 withholding）
   ↓
grounding.py         groundedness 评估：答案中 ≥10 万量级数字 vs 实际观测（1e-3 相对容差）
                     → 把"交了答案"细分为 correct / unsupported_numbers / no_terminal_response
   ↓
run_experiment_1_1.py  五臂驱动 + context_contract 逐轮合同检查 + canonical 判定 + latest.json 晋升
```

*`reasoning`（Ollama/OpenRouter 风格）与 `reasoning_content`（DeepSeek/vLLM 风格）双兼容——
这正是你在 064555Z 跑里亲手修掉的盲区（`96460497`），vLLM 后端会从另一条字段路径走过同一段代码。

## 一、阶段 0：vLLM 部署与连通预检（约 30 分钟）

**目标**：GPU 服务器上起一个带工具调用与思考解析的 vLLM 服务，并用两根探针确认它和
Ollama 行为同构。

```bash
# GPU 服务器上（模型 id 按 HF 仓库实际命名调整；显存不够时加 --max-model-len 8192）
vllm serve <Qwen3.5-9B 的 HF repo id> \
  --served-model-name qwen3.5-9b \
  --enable-auto-tool-choice --tool-call-parser hermes \
  --reasoning-parser qwen3        # 思考解析：没有它，reasoning 会混在 content 里

# 客户端（你的 WSL 或服务器本机）
cd chapter1/context
cat >> .env << 'EOF'
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://<GPU服务器IP>:8000/v1
OLLAMA_API_KEY=local-ignored
MODEL_NAME=qwen3.5-9b
EOF
```

两根预检探针（对应命令卡的 Ollama 版，vLLM 稍有不同）：

1. **模型与工具在位**：`curl http://<IP>:8000/v1/models` → 返回 `qwen3.5-9b`；
2. **思考上线探针**：发一条最小 chat 请求，确认响应 `message` 里有 `reasoning_content`
   （**注意**：vLLM 用 DeepSeek 风格字段名，Ollama 是 `reasoning`——harness 两种都认）。

**验收**：两探针通过。**常见坑**：漏 `--enable-auto-tool-choice` 会让所有臂的工具调用
静默失效（模型只能凭记忆作答，no_tool_calls 臂反而"看起来正常"——消融全部失真）；
漏 `--reasoning-parser` 会让思考文本混进 `content`，no_reasoning 臂的合同检查失败。

## 二、阶段 1：单臂快测（约 30 分钟）

**目标**：最小成本验证整条链路（部署 → harness → 工具执行 → 证据落盘）。

```bash
python run_experiment_1_1.py \
  --task guarded --hidden-result empty \
  --modes full --max-iterations 5 \
  --output-dir validation/probes_vllm_single_<时间戳>
```

**验收**：full 臂 `outcome=correct`，终文含两个期望值
（`9,602,895.73` / `2,400,723.93`）。打开 `evidence.json` 逐轮看三件事：
① 每轮请求的 `tools` 是否在位；② 响应 `reasoning_content` 是否非空；③
`tool_calls` 与工具观测是否配对。这三件事就是你判读任何一跑的基本功。

## 三、阶段 2：canonical 五臂复跑（约 1 小时）——核心交付

**目标**：在 vLLM 后端产出第二份本地 canonical（GPU 加速版），与 Ollama canonical
（`real_20261025T070721Z`）做**同 harness、不同部署层**的对照。

```bash
python run_experiment_1_1.py \
  --task guarded --hidden-result empty \
  --max-iterations 5 \
  --output-dir validation/real_<你的时间戳>
echo $?   # 0 ⇔ accepted 且已自动晋升 latest.json
```

**验收**：exit 0 + `Promoted` 字样。**对照表**（跑完填）：

|---|---|---|
| 五臂 outcomes | full/no_reasoning correct；双臂撞上限；no_tool_calls 编造 | ？ |
| 轮数（full） | 3 | ？ |
| 缓存命中率 | 80.6%（17,160/21,284） | ？（vLLM 前缀缓存统计看服务端日志） |
| no_reasoning 方向 | correct（n=1） | ？——再添一个数据点 |

**判读纪律**：单跑 n=1，方向不同不下"部署层导致"的结论——记录、对照、存疑，正像
晋升判定文档对 DeepSeek 基准的处理方式。

## 四、阶段 3：消融变体练习（各 30–60 分钟，可自由组合）

每个变体都带一个明确的问题，跑前先预测、跑后对答案：

| 变体 | 命令差异 | 你要回答的问题 | 已知参考行为 |
|---|---|---|---|
| 撤掉护栏 | `--task unguarded` | 没有"不得自行估计汇率"，no_tool_calls 臂还拒答吗？ | 账本实测：交回自估汇率的 $9,587,333.33（差 0.16%）——护栏是概率修正器不是开关 |
| 可见遮挡 | `--hidden-result marker` | 遮挡被"看见"后，行为分布怎么变？ | 账本实测：marker 1/4 撞上限 vs 静默 6/7 撞上限——消融自我宣告会改变行为 |
| 预算压缩 | `--max-iterations 2`（对 no_history/no_tool_results） | 撞上限的行为在更紧预算下如何表现？ | 观察重复调用模式是否更早暴露 |
| 温度阶梯 | `.env` 改 `MODEL_TEMPERATURE=0.0/0.7/1.0` | 编造翻转（2/4 vs 2/4）随温度怎么漂？ | n 足够前只记录不下结论 |

## 五、阶段 4：模型阶梯（半天，可选，GPU 允许时）

同一 harness 换更大模型（如 Qwen3.5-14B/32B，按显存选），重跑阶段 2。核心观察点只有一个：
**no_reasoning 臂的方向会不会翻转**——DeepSeek 云端基准 incorrect、qwen3.5:9b correct，
账本明言"换模型换结论"（手稿已改写为原则表述：推理携带 why、工具结果携带 what）。
你的每份数据都是这条原则的新样本。

## 六、阶段 5：判读、复核与入库（每阶段收尾 15 分钟）

1. **判读**：按 experiments 区四篇 1-1 判读文档的样式写：结论先行 → 逐臂解剖表 →
   与既有论断的对齐关系 → 数据点边界（n=1 声明）。
2. **复核**：`python3 docs/experiments/verify_chapter1_experiments.py`（28 项断言）；
   阶段 2 之后此脚本会自动校验你晋升的 latest.json。
3. **入库规范**（见 EXPERIMENT_CONVENTIONS.md）：未过验收门的跑放 `validation/probes_*/`
   不晋升；accepted 的 canonical 跑自动写 `latest.json`；证据含逐轮请求/响应但永不含凭据。

## 七、时间与依赖总览

| 阶段 | 用时 | 依赖 |
|---|---|---|
| 0 部署预检 | 0.5h | GPU + vLLM ≥ 支持 tool parser 的版本 |
| 1 单臂快测 | 0.5h | 阶段 0 |
| 2 canonical 五臂 | 1h | 阶段 1 |
| 3 变体（全做） | 2–3h | 阶段 1（不必等阶段 2） |
