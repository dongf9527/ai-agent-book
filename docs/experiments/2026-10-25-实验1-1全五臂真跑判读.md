# 实验 1-1 全五臂真跑判读：accepted=False 的精确根因是推理内容缺席

> 环境：WSL 内 Ollama（server v0.40.11），模型 `qwen3.5:9b`，2026-10-25。
> 命令：`python run_experiment_1_1.py --provider ollama --model qwen3.5:9b`（`--modes` 缺省即全五臂，
> 默认 `--task guarded --hidden-result empty`，canonical 口径）。
> 证据：`chapter1/context/validation/real_20261025T054152Z/evidence.json`
> （SHA-256 `e23851c86b6d0a12009918d8bded1ddd60c18bc8fbeea0359bbeb32e65b2b906`，**未晋升**）。
> 后记（同日第二次 canonical 跑）：A 档修复后推理已在 wire，被拦根因换位为合同/剥除层的
> 字段名盲区，且本文以 `usage.reasoning_tokens=0` 为证据的表述对该服务器不适用（该字段
> 恒 0）——见[第二次 canonical 跑判读](2026-10-25-实验1-1-第二次canonical跑判读.md)。

## 一、结论先行

**行为层全面达标，证据层被合同正确拦下。** 这是本地第一份五臂齐全的真跑证据，传输与
行为两个层面都没有问题：

- `exact_five_arms_present: true`——五臂齐全，不再是单臂快测的探针语义；
- `direct_real_api_evidence: true`——18 次请求全部有真实 provider 响应 id，无传输错误；
- `full_baseline_correct: true`——full 臂算出 **9,602,895.73 / 2,400,723.93**，验收门核心达成；
- `arms_stating_unsupported_numbers: []`——全程没有任何一臂编造汇率。

`accepted=False` 的唯一失效合取支是 `all_context_contracts_passed: false`，而它的精确根因
是：**服务端整跑没有回传任何推理内容**（`usage.reasoning_tokens = 0`），导致两个依赖
reasoning 的合同检查 fail-closed 落空（详见第四节）。

由此得到本次判读最重要的推论：**`no_reasoning` 消融在本跑中是空转的**。wire 上本来就
没有推理内容，"从历史里剥掉推理"删无可删——full 臂与 no_reasoning 臂在上下文层面完全
同构，一个 3 轮收敛、一个 4 轮收敛只是 temperature 0.3 下的随机涨落。因此
`without_reasoning_degraded: false` 在本跑中**既不能证实也不能证伪**手稿主张：消融没有
生效，观察不到差异是必然的。这与 DeepSeek 基准（推理确实在 wire 上、剥掉后
`no_reasoning` 臂失准为 `incorrect`）是两种完全不同的证据。

**没有 bug，无需修复工具包。** 这是 fail-closed 合同在正确履职：它拒绝为"名为 no_reasoning
实为 full 复读"的臂背书（第五、六节给根因与修复路径）。

## 二、验收门数学：为什么五臂齐了还是 false

```text
accepted = exact_five_arms ∧ contracts_pass ∧ direct_real_api ∧ full_baseline_correct
本跑:      true          ∧ false          ∧ true             ∧ true              → false
```

- `contracts_pass` 是五臂各自 `context_contract.passed` 的合取
  （run_experiment_1_1.py L498-500）。与单臂快测不同——那时 `exact_five_arms=false`
  直接短路，合同根本不评估——这次五臂齐全，`false` 是**真实的合同违约**，不是探针语义。
- 注意 `manuscript_behavior_claims`（4/5 已观察）**不在验收门内**，这是设计而非疏漏：
  验收门认证的是"实验执行本身受控"，行为主张是否复现属于证据文件的记录内容。
  账本（EXPERIMENT_LEDGER.md）也明确"运行时完成与手稿行为主张分开保管"。

| 臂 | 轮数 | outcome | 日志关键行为 | 判读 |

同一段 system+task 前缀，Ollama 的前缀缓存对消融跑这种"重复前缀"负载非常有效；
completion 6,568，全程约 1.5 分钟。

## 四、合同逐项定位：挂的是哪两处、为什么这是设计行为

五臂合同必过项中，只有两臂含 reasoning 依赖检查，其余三臂的检查全部通过：

| 臂 | 挂掉的检查 | 检查内容（run_experiment_1_1.py） |
|---|---|---|
| full | `reasoning_retained_after_first_turn` ❌ | 第 2 轮请求的 assistant 消息应携带上一轮的 `reasoning_content`（L193-198）——服务端从未回传，无从携带 |
| no_reasoning | `provider_generated_reasoning` ❌ | 至少一轮响应应含推理内容（L248-253）——18 轮响应全部没有 |
| full 其余三项 | ✅ | 响应 id 齐全 / 每轮有 tools / 第 2 轮起有 assistant+tool 历史 |
| no_reasoning 其余三项 | ✅ | `reasoning_removed_from_history` 空真成立（本就无推理）/ tool 消息历史仍在 |
| no_history / no_tool_calls / no_tool_results | ✅ 全过 | 三臂合同不含任何 reasoning 依赖 |

**fail-closed 的意义**：合同认证的是"消融确实发生"。若放行本跑，证据文件将永久记录一个
名叫 `no_reasoning`、上下文与 full 完全相同的臂——读者会据它得出"剥掉推理不影响正确性"
的结论，而实际上什么都没被剥掉。这与 `arm_produced_inference()` 防"402 空转也报成功"
的动机一脉相承：证据文件绝不记录它无法担保的事。

## 五、根因：agent.py 只对 deepseek 显式开了 thinking

- `agent.py` L782-784：仅当 `provider == "deepseek"` 且非 OpenRouter 时，请求附加
  `extra_body = {"thinking": {"type": "enabled"}}`，以保证 wire 上有 `reasoning_content`。
  **ollama 分支没有任何对应开关**——是否回传推理完全取决于模型与服务端默认。
- 读取端没有问题：`_reasoning_content()`（L554-560）已兼容 `reasoning_content` 与
  extra 里的 `reasoning`（后者正是 Ollama 原生字段名）。服务端若回传，必然被捕获进
  `trajectory.reasoning_steps` 并写进合同检查依据。`reasoning_steps` 为零、
  `reasoning_tokens` 为零，说明**服务端确实没回**，而非 harness 没读。
- 对照组：accepted 基准 `deepseek-v4-flash` 的三次真跑（`real_20260729T153329Z` /
  `real_20260825T025409Z` / `real_20260901T163146Z`）contracts 全过、
  `no_reasoning` 臂 reasoning_steps 达 2——因为 thinking 被显式打开，消融真实生效。
- 所以问题不在"qwen3.5:9b 不会推理"，而在两可之间：模型默认关思考，或 `/v1` 端点
  未透传思考内容。第六节的探针负责把这两可变成确定。

## 六、在你机器上的三步实锤

```bash
# ① 模型能力：Capabilities 里是否列出 thinking
ollama show qwen3.5:9b | head -20

# ② 证据文件挂点实锤（确认合同失败确实落在 reasoning 检查上）
cd /mnt/e/sourcecode/ai-agent-book/chapter1/context
python3 - <<'EOF'
import json
d = json.load(open('validation/real_20261025T054152Z/evidence.json'))
for arm in d['arms']:
    if arm['mode'] not in ('full', 'no_reasoning'):
        continue
    cc = arm['context_contract']
    print(f"== {arm['mode']}  passed={cc['passed']}")
    fails = [k for k, v in cc.items() if v is False]
    print("   failed checks:", fails or "none")
    for t in arm['api_turns']:
        msg = t['response']['choices'][0]['message']
        has = bool(msg.get('reasoning_content') or msg.get('reasoning'))
        print(f"   it{t['iteration']}: reasoning_on_wire={has}")
EOF

# ③ 服务端能否吐推理（两个端点分别探）
curl -s http://localhost:11434/api/chat -d '{"model":"qwen3.5:9b","messages":[{"role":"user","content":"9.11 与 9.8 谁大"}],"think":true,"stream":false}' \
  | python3 -c "import json,sys; m=json.load(sys.stdin)['message']; print('native think →', bool(m.get('thinking') or m.get('reasoning')))"

curl -s http://localhost:11434/v1/chat/completions -d '{"model":"qwen3.5:9b","messages":[{"role":"user","content":"9.11 与 9.8 谁大"}],"reasoning_effort":"high"}' \
  | python3 -c "import json,sys; m=json.load(sys.stdin)['choices'][0]['message']; print('/v1 effort →', bool(m.get('reasoning') or m.get('reasoning_content')))"
```

判读：① 列出 thinking 且 ③ 两条任一为 True → 走第七节 A 档（一行改动）；
③ 两条全 False 但模型确有思考能力 → 端点/版本问题，先升级 Ollama 再探；
① 无 thinking 能力 → 走 B 档。

## 七、修复路径分档

- **A. 服务端支持、仅缺开关**：`agent.py` 的 ollama 分支补一行，对齐 deepseek 先例
  （探针证实字段名后落地，`request_data` 同步记录以保持证据完整）：
  ```python
  if self.provider == "ollama" and not getattr(self, "using_openrouter", False):
      create_kwargs["extra_body"] = {"reasoning_effort": "high"}  # 或探针证实的其他字段
      request_data["reasoning_effort"] = "high"
  ```
  改完重跑全五臂：若合同转绿且五臂 claims 与基准可比，即产生第一份本地 canonical 证据。
  （2026-10-25 更新：A 档已按 `reasoning_effort=high` 落地进 `agent.py`，`OLLAMA_THINK=0`
  可关；完整操作序列见 [canonical-run 命令卡](2026-10-25-实验1-1-canonical-run命令卡.md)。）
- **B. 模型无思考模式**：本地教学跑改用四臂
  `--modes full no_history no_tool_calls no_tool_results`——`no_reasoning` 臂对无思考模型
  天然退化为 full 的复读，硬跑只会得到本跑的复制品；或 `ollama pull` 一个默认吐推理的
  思考型模型再跑五臂。
- **C. 暂不动**：canonical 结论继续引用 DeepSeek 的 `validation/latest.json`（accepted=true），
  本次证据留档 `real_20261025T054152Z` 不晋升，作为"fail-closed 合同真实触发"的教学案例。
- 无论选哪档，建议把 `validation/real_20261025T054152Z/` 与 `real_20261025T052851Z/`
  从你的检出提交入库：未晋升的证据目录本身就是仓库惯例的一部分（probes_* 目录即先例），
  它们记录的是本地复现史，不影响 `latest.json` 的权威性。

## 八、与 canonical 基准对照：同一 harness、同一任务、两个模型

| 臂 | deepseek-v4-flash（accepted 基准） | qwen3.5:9b（本跑，消融未生效） |
|---|---|---|
| full | `correct` | `correct` ✅ 同型 |
| no_history | `no_terminal_response`（5 轮） | `no_terminal_response`（5 轮）✅ 同型 |
| no_reasoning | `incorrect`（推理在 wire、剥掉后失准） | `correct`（**不可比**：无推理可剥） |
| no_tool_calls | `unsupported_numbers`（编造汇率） | `no_unsupported_numbers`（未编造）⚠️ 相反 |
| no_tool_results | `no_terminal_response`（5 轮） | `no_terminal_response`（5 轮）✅ 同型 |

`no_tool_calls` 一行的分歧是本次最有趣的数据点：同一 guarded 任务，DeepSeek 编造了
汇率，qwen3.5:9b 没有编。账本对这一现象早有定性——"编造倾向是模型自身的主因，
prompt 约束只是修饰因子"——本跑提供了 n=1 的反向样本，方向一致但样本太小，不足以下
模型间结论；它真正的价值在于演示了 `outcome` 分类为什么必须存在：两臂都是"完成"，
一个交回了看似合理的错误数字，一个没有，`completed` 字段对二者一视同仁，只有
groundedness 能把它们分开。

一句话总结：**4/5 手稿行为在本地开源模型上复现，验收门核心（full 臂正确）通过，
被拦下的只是"消融是否真实发生"的合同认证——这正是证据体系按设计工作的样子。**
